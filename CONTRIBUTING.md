# Reproductions and contributions

Open an issue with the example path, n8n/Node version, reproduction steps, expected result and actual result. Use synthetic data and redact secrets. Never include API keys, tokens, cookies, customer records, or private URLs.

Before a pull request, run the example tests. For visual changes, render the preview and inspect first/middle/final frames. Document all asset origins and dependencies. Avoid unsupported performance claims or changes that weaken validation.
